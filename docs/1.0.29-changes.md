# Fornalhas Tech 1.0.29

Base commit: `dfae3abb7c3fa819dcd2f4df39bca5946ddddcaa` (`main`, 1.0.28)

## Corner cube adjustment

The eight existing vertex cube assemblies in the Base, neutral and animated block models move a further 0.125 model units toward the block center along X, Y and Z. Low coordinates move by +0.125; high coordinates by -0.125. The corner detail quads in `TechFurnaceEnergyRenderer` receive the matching 0.125/16 = 0.0078125 block shift. Cube dimensions, orientation, 24 recessed color details, edge-frame absence, and texture/UV mapping are unchanged. Resulting centers are 0.5 or 15.5 model units on each axis, and cubes remain positively protruding.

## Five-frame lower-front fire

The five 64x32 RGBA files `fire_panel_0.png` through `fire_panel_4.png` are transparent pixel-art overlays. `TechFurnaceEnergyRenderer` draws one frame in the inner lower front opening only, in Base mode, while the block state's actual `LIT` property is true. The panel is bounded by x=4.75..11.25, y=2.50..5.75 model units, just in front of the existing dark panel; no face geometry or dark panel texture is changed. The same facing rotation as the existing front effects is applied. A three-tick frame cadence loops all five frames. This intentionally follows combustion (`LIT`), including when no recipe ingredient is present, and stays active through an immediate fuel handoff.

## Cooking particles and redstone

Client `animateTick` creates small vanilla dust particles only while `COOKING` is true, using the exact technology color from the block's selected visual color mapping. `COOKING` is the server-synchronized existing state that means recipe work progressed and output is available. Weak and direct redstone signal are 15 only for that state. The block entity changes `COOKING` only when the state differs and calls `setBlock` with neighbor-update flags 3, so redstone neighbors update on start/stop transitions, not every tick. Analog comparator output reports the existing inventory fullness signal.

Fuel handoff, cooking speed, block light levels and GUI are unchanged. The 1.0.29 validator verifies the changed geometry and required effect conditions; the existing energy phase, fuel work, and light level tests remain in the GitHub Actions workflow.
