# Fornalhas Tech 1.0.31

Base: `main` at 1.0.30 (`4a639e77417c955c21739690bacd8d90ae1ffe37`).

## Fire animation

Only the five lower-panel fire overlay PNGs were redrawn. Each remains 64x32 RGBA and uses the renderer's existing lower-front-panel quad, directional mapping, lighting gate, and frame cadence. Opaque flame pixels cover at least 90% of the image area in every frame; the remaining transparent pixels are small intentional gaps that reveal the original dark panel. The frame data was measured at native resolution, rather than treating the quad bounds as coverage.

The frames sample a lateral sway cycle: left (-5 px), near center (-1 px), right (+5 px), near center (+1 px), and easing left (-4 px). Each row is sheared by a height-dependent offset, so the bottom five pixel rows remain identical while the upper flame tongues move laterally. Their irregular top silhouette and red/orange/yellow pixel layers remain sharp.

No Java render or processing logic changed. Existing `FACING`-specific placement for NORTH, EAST, SOUTH, and WEST, burn-state gating, fuel handoff continuity, particles, redstone, light, inventory, and recipes remain unchanged.

## Verification

The validator decodes the RGBA PNG pixels using only Python's standard library. It checks >=90% alpha coverage for each frame, remaining transparent pixels, identical bottom five rows, and bright-tip centroid order left-to-right-to-left. The workflow also runs the existing Java 17 Gradle build and regression checks. Minecraft visual testing is still required to confirm the rendered cycle in game.
