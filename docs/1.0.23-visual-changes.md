# Fornalhas Tech 1.0.23

Base: main / 218e6ec541944b0cc7f80352c12e763f9a46e144 (1.0.22).
Minecraft 1.19.2, Forge 43.5.0, Java 17, Gradle 7.5.1 unchanged.

## Geometry

The first 12 frame bars and 8 corner cubes in both current Base models are scaled once.
Bars: transverse thickness 1.375 -> 1.03125; external projection 1.25 -> .9375.
Length .25..15.75 remains unchanged. Cubes: side 2.625 -> 1.96875;
half-side / outward projection 1.3125 -> .984375, centered at each original 0/16 vertex.
Both outward projections scale by .75, preserving their previous ratio.
All elements after the first 20 are byte-for-byte structurally equal in the static models.
The previously closed sidewalls, internal body and recessed depth .372 remain unchanged.

## Six 64px metal faces

A restrained neutral brushed-iron material was created with the built-in image tool and
sampled by nearest neighbor. Prompt: seamless 64 logical pixel worked iron, grayscale,
subtle organized horizontal streaks, stepped highlights, no rivets/seams/random noise.
The material is applied at low, quantized contrast only within existing #BBBBBB and #343434
regions. One-pixel edge shading follows existing panel boundaries. Black outlines, dark
#090909 cooking openings, neutral color pixels and all alpha masks remain unchanged.
The bottom is refined as metal but receives no color animation. Core item textures are untouched.

## Five-frame energy flow

Five static, precomputed grayscale PNG sheets, each 64x320 (five separate 64x64 face tiles in
North/South/West/East/Up order), contain the same exact emissive masks as 1.0.22.
Only brightness changes. Shortest-path distance through connected channel pixels produces
ordered traveling pulses. The five phases sample a periodic wave at equal intervals.
No texture is decoded/generated/uploaded repeatedly by custom runtime code.
Nearest filtering is explicit in texture metadata; there is no global .mcmeta animation clock.

A client BlockEntityRenderer draws only these five masked recessed faces, with the exact
same UV orientation, coordinates and .372 depth as the old static emissive caps.
It uses the existing BlockColors handler, preserving all approved core/customization colors.
Color 0 retains the existing neutral, non-emissive appearance; no new color rule is introduced.
World model variants use a new structural model without the old emissive caps. The static
Base model remains available for the block item so its channels do not disappear in inventory.
Other module models are unchanged.

EnergyFlowPhase is keyed per block entity in a weak map; it is client-only, not saved or sent
across the network. COOKING selects 4 ticks/frame while processing; otherwise 12 ticks/frame.
Cycles are 20 and 60 ticks. Existing LIT/CORE illumination logic is not changed.
Changing activity alters speed without resetting phase. Linear interpolation blends the current
opaque masked frame with the next frame at identical coordinates, in ordered emissive passes.
The five-to-zero transition uses the same interpolation. No static coplanar emissive caps remain
under the dynamic faces. At most ten quads and two material passes per visible animated block;
metal geometry stays baked. No per-frame model rebuilding or world-light updates.

Forge registration follows its [1.19.x BER documentation](https://docs.minecraftforge.net/en/1.19.x/blockentities/ber/).
The Pinterest short links supplied with the request were inaccessible during retrieval;
the attached concepts and written effect specification were used.

`python tools/build_visuals_1_0_23.py --baseline <pristine-1.0.22> --metal docs/1.0.23-metal-source.png --output .`
The generator rejects an already reduced input. Run validation against the same baseline:
`python tools/validate_visuals_1_0_23.py --baseline <pristine-1.0.22> --root .`
The committed images are final assets; generation is not part of the mod's runtime/build.
