# Fornalhas Tech 1.0.26

Origin: main / 5bf1b6c3628f1bd65956651b278d3859156b8b23 (1.0.25).
Minecraft 1.19.2, Forge 43.5.0, Java 17 remain unchanged.

## Exact geometry change

Only the current Base/static item, neutral and animated Base models are edited.
The first twelve longitudinal bars (4 top, 4 bottom, 4 vertical) are removed.
The eight original corner envelopes retain their exact positions and dimensions:
side 1.96875; centers at all eight combinations of 0 and 16. Their outward
projection remains .984375. No second size reduction is applied.

Each corner has one hole in each of its three outward faces: exactly 24.
Hole side .196875 is exactly 1/10 of the cube width, not 10% of face area.
Depth .024609375 equals one eighth of hole width, a subtle genuine recess.
Four metal surface rectangles surround each open aperture. Four inward-facing
walls connect the aperture to its sealed light cap. The old full metal face is
removed behind the aperture, so the light is not buried inside a solid face.
The metal surface UVs are interpolated from the original full-face UV mapping.
Cube inward faces stay intact. No extra cullface hides the protruding details.

All model elements after the former first twenty (12 bars / 8 cubes) are
structurally identical to 1.0.25, including the closed internal body and all
six face reliefs. All six metallic face PNGs, UVs, masks and existing animation
textures are unchanged. Blast-furnace/smoker models are unchanged.

## Existing tint and animation integration

The static block-item model has 24 white tinted emissive caps; the neutral
model has 24 non-emissive caps in the existing neutral RGB (154,166,170).
Two 1x1 PNGs provide these solid materials without altering any old texture.
Metal rims and cavity walls retain normal ambient lighting.

The animated world model omits the 24 static caps. The existing BER draws them
at precisely the same recessed coordinates, using the same BlockColors result,
five texture frames, interpolation, LIT state, 12/4 ticks per frame and per-entity
clock as the original channels. All squares sample one fully opaque existing
channel texel (8,7 of the north tile); frame intensities are 246,231,186,174,213.
A uniform animated shade is deliberate because each square is very small.
No timer, network traffic, saved field or world-light updates are added.
At most 29 masked quads per pass / 58 with interpolation, using the same two
cached render materials as before. No performance benchmark is claimed.
Rotation uses the existing common pose transform for both channels and caps.

## Verification actually performed

The geometry validator uses exact rational numbers to check all eight original
cube envelopes, 24 centers, 10% widths, exact depths, four rims/four walls per
hole, sealed static caps, full-face area coverage and unchanged remaining
geometry in all three JSONs. All twelve old bar elements are absent.

Software renderings read the actual JSONs, textures and UVs: before/after,
six orthographic faces and a close-up of three recessed corner lights.
These are diagnostic renders, not Minecraft screenshots. The exact small size
means the points may be subpixel at distance; this is not a new geometry size.

Existing Actions Java 17 build and animation/fuel/light regression tests are
preserved. Gameplay, GUI, recipes, fuel, lighting levels and persistence classes
are untouched. JAR comparison verifies the preserved resources/classes.

Pending Minecraft checks: actual shader/depth behavior, tiny-square visibility
at multiple distances, adjacent blocks, all core/customization colors, resource
reload, and live animation while burning/idle. Visual approval is not claimed
from compilation or software previews alone.

## Reproduction

With Pillow and NumPy installed:
`python tools/build_corner_details_1_0_26.py --baseline <pristine-1.0.25-project> --output <output-project>`
The output project must have a docs directory. Validate against the same baseline:
`python tools/validate_corners_1_0_26.py --baseline <pristine-1.0.25-project> --root <output-project>`
The final generated assets are committed; neither Python nor image generation
runs while playing Minecraft.
